# PRD-003：异步图像识别任务

| 字段 | 内容 |
| --- | --- |
| 当前版本 | v1.0.0 |
| 创建日期 | 2026-09-03 |
| 状态 | 可开发 |
| 基线文档 | PRD-002、整页作业拍照识别与逐题批改规格、ADR-0001 |
| 变更性质 | 为单题讲解和作业批改引入可靠的异步图像识别闭环 |

## 问题陈述

家长拍摄一道题或上传整页数学作业后，系统当前在小程序请求内同步调用视觉识别模型。模型虽然可返回 HTTP 成功状态，但完整响应有时超过微信云托管 `CallContainer` 约 15 秒的客户端时限，导致用户看到网络超时或识别失败。延长同步超时无法稳定解决问题，并且整页图片的 Base64 请求体还可能超过云托管限制。

家长需要一个可恢复、可重试且不依赖页面持续打开的识别过程；识别慢或短暂失败时，不能丢失图片、草稿、家长确认权或手动录入入口。

## 解决方案

“拍一道题”和“批改作业”统一改为异步图像识别任务。小程序将图片直传腾讯云对象存储，向业务后端创建任务后立即得到任务 ID；业务后端将任务持久化至线上 MySQL，并异步调用腾讯云函数 Worker。Worker 仅接收任务 ID，从 MySQL 和对象存储读取所需数据后调用 DeepSeek，将脱敏状态和结构化结果写回 MySQL。小程序每秒查询任务状态，完成后进入既有题干确认或逐题作业批改流程。

系统继续使用 DeepSeek 视觉能力。本期解决的是同步链路时限问题，而不是替换模型供应商。AI 输出仍为 AI 初判，只有家长确认的批改结果才影响错题本、正确练习证据、掌握度、薄弱点、复习计划和周报。

## 用户故事

1. 作为家长，我想在拍摄一道题后立即看到“识别中”，以便确认系统已接收图片而不是卡在提交页面。
2. 作为家长，我想在识别慢于小程序请求时限时仍获得结果，以便不因网络超时重复拍摄或丢失草稿。
3. 作为家长，我想从相册选择一道题图片后继续识别，以便使用已拍摄的清晰图片。
4. 作为家长，我想在识别任务完成后查看并修改题干、公式、作答和题目区域，以便单题讲解基于正确内容进行。
5. 作为家长，我想上传一页作业后让系统在后台识别多道题，以便不受同步请求超时影响。
6. 作为家长，我想在作业识别完成后逐题查看 AI 初判，以便保留对每题结果的最终决定权。
7. 作为家长，我想在离开识别页面、切换小程序或网络短暂中断后继续等待任务，以便不因页面生命周期丢失识别工作。
8. 作为家长，我想回到相关页面时恢复未完成或已完成的识别结果，以便无需重新上传同一张图片。
9. 作为家长，我想在任务失败时点击重试，以便对短暂模型故障再次发起识别。
10. 作为家长，我想在识别无法完成时改用手动录入，以便不被 AI 服务阻塞。
11. 作为家长，我想看到清晰且可行动的失败提示，以便知道是重试、重新拍摄还是手动录入，而不是看到模型或云服务内部错误。
12. 作为家长，我想在图片不清晰或没有数学题时得到明确提示，以便重新拍摄更合适的内容。
13. 作为家长，我想知道正在处理的识别任务不会因为服务重启而丢失，以便信任识别进度。
14. 作为家长，我想避免因网络重试而重复扣减识别额度，以便控制家庭的使用配额。
15. 作为家长，我想在同一时间只等待一个任务，以便避免误操作创建多笔重复识别。
16. 作为家长，我想让单题讲解和作业批改的识别体验一致，以便学习同一套操作方式。
17. 作为家长，我想让临时识别图片在合理期限后清理，以便减少孩子作业图片长期留存。
18. 作为家长，我想确认错误题后才将其沉淀为错题，以便 AI 的不确定判断不污染学习统计。
19. 作为运营人员，我想从脱敏任务日志看到模型响应耗时、状态和重试情况，以便排查稳定性和成本问题。
20. 作为运营人员，我想限制并发和自动重试，以便模型波动时不会造成重复调用和费用失控。

## 实施决策

- 识别任务使用 `kind` 区分 `single_question` 与 `homework_page`；两类任务共用创建、查询、重试、过期、授权和审计规则，但保留各自的结构化识别结果。
- 小程序创建任务时只提交孩子档案、草稿或作业关联信息、对象存储 `fileId/imageKey` 与幂等键；不得将整图 Base64 放入云托管请求体。
- 创建接口立即返回任务 ID 和初始 `pending` 状态。状态查询接口仅返回当前家长账户有权访问的任务，状态为 `pending`、`processing`、`succeeded` 或 `failed`；成功时返回识别结果，失败时返回面向用户的可行动错误代码。
- 小程序在识别页面每 1 秒查询一次任务状态，最长等待 60 秒；完成、失败、页面卸载或新任务替代旧任务时停止轮询。任务在页面离开后继续运行，页面返回时恢复任务状态。首版不接入订阅消息。
- 业务后端将任务写入线上 MySQL 后，使用腾讯云函数异步调用 API 触发 Worker；调用不等待 Worker 完成。Worker 只接收任务 ID，不接收图片内容、业务访问令牌或微信登录凭证。
- Worker 从 MySQL 原子领取任务，读取对象存储临时 URL，调用 DeepSeek，并将结果、状态、尝试次数、耗时及脱敏失败信息写回 MySQL。Worker 不依赖云托管容器的后台线程、内存或本地磁盘。
- 线上图片使用腾讯云对象存储保存。任务图片和临时识别所需引用保留 24 小时；任务记录、识别结果和脱敏审计信息保留 7 天，之后由清理机制删除。仅沿用既有“作业图片保留”规则长期保留家长主动选择的已确认错误题裁剪图。
- 单任务最长处理 60 秒。仅超时、网络错误、429、500、503 等临时错误可自动重试，最多 2 次；400、401、403、422 等不可恢复错误直接失败。用户主动重试创建新的尝试记录，不覆盖原失败记录。
- 同一家庭同时最多 1 个运行中的识别任务。识别任务纳入既有拍题额度；超出配额时不得创建任务，并继续提供手动录入。
- 使用客户端幂等键防止请求重放。同一家长账户、同一幂等键在任务终态前必须返回同一任务，不得重复调用模型或重复扣减额度。
- 云托管调用云函数所需的地域、函数名、命名空间及身份凭据均通过线上环境配置提供。使用最小权限的子账号或角色，仅授予异步调用指定函数、读取所需对象、访问任务所需 MySQL 的权限；不得写入小程序、代码仓库或应用日志。
- DeepSeek 继续作为视觉模型提供方。视觉输入使用对象存储临时 URL，并按供应商支持的低细节参数降低时延；提示词和结构化结果需限制不必要的解释性输出。供应商响应、输出 token、完成原因、耗时和重试信息以脱敏方式记录。
- 用户错误文案固定为可行动的业务状态：临时故障提示“识别服务繁忙，请重试”；无清晰数学题提示重新拍摄或手动录入；格式或大小不支持提示使用清晰 JPG/PNG；未知故障提示稍后重试。不得暴露 DeepSeek、腾讯云、密钥、临时 URL、openid、请求体或堆栈。
- 所有任务创建、查询、重试和结果读取必须校验家长账户、孩子档案及草稿/作业归属。任务 ID 不得成为跨账户访问学习图片或结果的凭据。
- 成功的单题任务进入既有题干确认和讲解流程；成功的作业任务进入既有候选题确认流程。ADR-0001 继续适用：AI 初判不直接产生学习记录。
- 最高验证 seam 为 HTTP 任务 API 与持久化任务状态的端到端合同：以存储图片引用创建任务、触发 Worker、查询终态，并验证后续的家长确认对学习闭环的影响。

## 测试决策

- 测试以外部可见的任务创建、状态变化、授权边界、识别结果和家长确认结果为断言对象，不绑定 Worker 的内部函数调用顺序、具体提示词或云 SDK 实现。
- HTTP 合同测试覆盖：创建单题和作业任务立即返回任务 ID；任务状态仅对所属家长可见；成功与失败终态返回正确合同；无会话、越权档案、无效图片引用和重复幂等键得到明确结果。
- Worker 集成测试覆盖：任务原子领取、对象存储临时 URL 解析、DeepSeek 成功结果写回、超时/429/500/503 的重试、不可恢复错误失败、最多 2 次自动重试与 60 秒终止。
- 学习闭环测试覆盖：异步识别成功不直接创建错题；家长确认错误后创建错题和复习计划；确认正确后创建正确练习证据；待确认题不进入统计。这些行为沿用现有学习闭环测试的领域语义。
- 小程序流程测试覆盖：创建后显示识别中、每秒轮询、页面返回后恢复、完成后进入相应确认页、失败后的重试/重新拍摄/手动录入、轮询在离开页面和终态后停止。
- 安全与隐私测试覆盖：图片 Base64 不进入任务创建请求和日志；任务 ID 越权访问失败；日志中不存在 API 密钥、临时 URL、openid、微信 code、图片内容或完整模型响应。
- 清理任务测试覆盖：24 小时图片引用和 7 天任务记录的过期清理，且不会删除既有规则允许长期保留的已确认错误题裁剪图。
- 使用虚构家长账户、孩子档案、图片引用和固定模型响应 fixture；不使用真实未成年人作业、身份数据或生产凭据。

## 不在范围内

- 本期不切换到腾讯 AI 或引入第二个视觉模型供应商。
- 本期不引入消息队列、定时扫描 Worker 或多地域任务调度。
- 本期不接入微信订阅消息来通知识别完成。
- 本期不支持一次上传多页作业、连续扫描整本作业或教师端批改。
- 本期不改变 AI 初判必须由家长确认的领域规则。
- 本期不提供任务历史的长期用户可见列表、公开分享、原图用于模型训练或绕过家长授权的访问方式。

## 进一步说明

- 腾讯云函数是新增的执行资源；线上继续复用现有腾讯云对象存储和 MySQL。云托管 `ctb` 只承担任务 API 和异步触发，不等待 DeepSeek 识别完成。
- 不引入消息队列的前提是云函数异步调用的投递与失败配置满足当前任务量；若未来需要更严格的削峰、积压可视化或多 Worker 并发控制，再单独评估消息队列。
- 该 PRD 不取代整页作业区域编辑、逐题确认及手动录入规格，而是为单题和整页视觉识别提供稳定的执行边界。
