# 孩子档案省份与教材字段首版策略

**Status:** resolved

## Problem Statement

首版孩子档案的地区选择使用了省、市、区级联控件，增加了建档负担；同时教材版本字段目前没有参与任何学习逻辑。产品需要保留未来按省份和教材适配课程内容的空间，并兼容已经保存的旧版省市档案，但不应在首版收集无实际用途的细粒度地区信息。

## Solution

将地区收敛为可选的省份字段。新版本使用自定义单列省份选择器，用户可以跳过选择；页面只展示省份。服务端继续接受并保留旧客户端提交的省市数据，但不再要求城市或区县。教材版本字段保留在后端和历史数据中，首版界面隐藏，不参与识别、讲解、复习或推荐。

## User Stories

1. 作为家长，我想只选择省份，以便快速完成孩子建档。
2. 作为家长，我想跳过省份选择，以便不提供当前没有实际用途的位置资料。
3. 作为家长，我不想看到市、区县级联选择，以便减少选择成本和误操作。
4. 作为家长，我想在档案列表中只看到省份摘要，以便快速确认档案信息。
5. 作为旧版本用户，我想继续读取已有的省市档案，以便升级后学习数据不受影响。
6. 作为旧版本用户，我想编辑旧档案而不被强制重新选择城市，以便兼容历史资料。
7. 作为发布负责人，我想让旧客户端提交省市仍被服务端接受，以便灰度升级期间新旧客户端可以共存。
8. 作为产品负责人，我想保留省份字段，以便未来按省份适配教材或课程标准。
9. 作为产品负责人，我想暂不启用教材适配逻辑，以便首版保持范围可控。
10. 作为家长，我想教材版本不是必填项，以便没有明确教材信息时仍可完成建档。
11. 作为发布负责人，我想省份缺失不会阻断识别、讲解、复习和周报，以便地区信息不是隐藏的首版依赖。
12. 作为数据管理员，我想历史城市字段不被删除，以便未来需要迁移或分析时仍有来源数据。

## Implementation Decisions

- 孩子档案输入模型将省份代码和名称作为可选值；城市代码和名称仅作为旧数据/旧客户端兼容字段。
- 新版小程序使用单列省份选择器和内置省份代码、名称映射，不使用省、市、区级联控件。
- 新版创建和编辑请求只提交省份字段；省份未选择时省份字段省略或为空。
- 服务端接受仅省份、无地区字段以及旧版省市输入；省份存在时校验代码和名称格式，城市字段若成对出现则继续校验。
- 存储层能够保存和读取仅省份档案，并保留历史省市列；读取旧档案时向客户端提供兼容数据，但界面只显示省份。
- 教材版本继续作为可选持久化字段保留；首版小程序不展示输入控件，也不让其改变任何业务规则。
- 省份和教材版本不参与题目识别提示、讲解生成、变式题推荐、复习调度、额度或周报统计。

## Testing Decisions

- 在 `LearningLoop` 公共接口测试省份缺失可建档、省份格式校验、仅省份档案读写和旧省市输入兼容。
- 在 HTTP API seam 测试省份字段的创建/更新请求契约，以及省份缺失不影响后续业务接口。
- 在存储 seam 测试旧省市记录读取后仍保留数据，新增仅省份记录可恢复。
- 在小程序验收清单中确认选择器只有省份、跳过选择可保存、旧省市档案页面只展示省份。
- 测试只验证用户可见行为和接口契约，不依赖第三方 picker 或数据库内部实现细节。

## Out of Scope

- 按省份自动选择教材、课程标准或知识点映射。
- 教材版本字典、教材章节同步、地区化题库和个性化推荐。
- 收集或展示城市、区县的新功能。
- 删除或批量清洗历史省市数据。

## Further Notes

省份字段是未来适配的预留数据，不代表首版已经提供地区化学习能力。真正启用教材适配前，需要另行定义教材版本枚举、知识点映射、模型提示策略和验收样本。
