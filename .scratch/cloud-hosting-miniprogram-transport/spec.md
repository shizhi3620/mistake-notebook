# 小程序云托管调用与单生产环境灰度发布

**Status:** ready-for-agent

## Problem Statement

当前小程序 API 客户端以 `wx.request` 调用每个环境的 HTTPS API 域名，正式环境因而依赖可绑定、可备案的自定义域名。微信云托管已提供小程序专用的 `wx.cloud.callContainer` 调用链路；继续使用普通 HTTPS 域名既增加备案与配置成本，也与单一生产云托管环境的发布方式不匹配。

团队决定首版仅面向微信小程序，不提供浏览器、H5 或第三方对外 API 调用。服务版本验证将在本地 Docker 完成常规回归，并在唯一生产云托管环境中通过白名单和灰度完成平台集成验证。

## Solution

小程序 API 客户端按小程序环境选择传输方式：开发版继续调用本地 Docker 暴露的 HTTPS API；体验版和正式版通过微信云托管 `callContainer` 调用生产环境的 `ctb` 服务。现有 `/api` HTTP 契约、微信登录交换、业务 session、Bearer token 与幂等键均保持不变。

云托管控制台负责对同一服务的版本灰度：指定测试 `openid` 先访问新版本，验证通过后按 5%、25%、100% 放量并结单；异常立即回退。小程序不携带灰度版本参数。

## User Stories

1. 作为小程序家长，我希望正式版可直接调用云托管服务，以便不受自定义域名备案进度影响。
2. 作为小程序家长，我希望登录、拍题、讲解、错题本、复习和反馈的请求行为保持不变，以便升级不影响既有使用。
3. 作为体验版验收人员，我希望自己的 `openid` 被路由到待验证服务版本，以便在不影响普通用户的情况下验收发布。
4. 作为正式版用户，我希望在灰度期间继续命中稳定服务版本，以便避免未验证版本影响学习数据。
5. 作为发布负责人，我希望可按 5%、25%、100% 逐步放量并随时回退，以便控制单生产环境的发布风险。
6. 作为开发者，我希望开发版仍可调用本地 Docker 的 HTTPS API，以便日常调试不写入生产数据。
7. 作为开发者，我希望体验版和正式版共享同一云托管调用配置，以便避免客户端灰度参数与服务端路由规则不一致。
8. 作为家长，我希望 session 过期后的重新登录与现有行为一致，以便不因传输层迁移丢失恢复能力。
9. 作为家长，我希望提交型操作继续携带幂等键，以便重试不会创建重复学习记录或反馈。
10. 作为发布负责人，我希望服务名和环境 ID 由私有环境配置提供，以便避免将部署绑定信息散落在页面代码中。
11. 作为低版本微信用户，我希望收到明确的升级提示，以便知道无法调用云托管的原因。
12. 作为运营人员，我希望普通小程序调用不依赖默认域名或自定义域名，以便不把临时浏览器域名误用为正式入口。
13. 作为安全负责人，我希望现有 API session、运营 secret 和权限校验继续在云托管后端生效，以便网关调用不削弱业务授权边界。
14. 作为测试负责人，我希望 Docker、本地 HTTPS 调试和生产灰度各自覆盖明确范围，以便问题能被定位到正确环境。

## Implementation Decisions

- 小程序生产调用的唯一云托管环境 ID 为 `prod-d8giqy4sjc5925f68`，服务名称为 `ctb`。
- 开发版使用私有配置中的 HTTPS API 基址，指向本地 Docker 的 HTTPS 隧道或等效开发 API；开发版不得默认调用生产云托管服务。
- 体验版和正式版使用 `wx.cloud.callContainer`。请求路径保持既有 `/api/...` 前缀，HTTP 方法、JSON body、Bearer token、`Idempotency-Key` 与错误处理语义保持一致。
- 体验版和正式版请求设置 `X-WX-SERVICE: ctb`；服务名称按小程序环境存放于 Git 忽略的私有配置中。环境 ID 和服务名称不是业务密钥，但不得在页面中重复硬编码。
- 小程序启动时继续初始化云开发；API 客户端在调用前检查基础库是否至少为 `2.13.1`。不满足时给出升级微信的明确错误，不回退到默认域名或自定义 HTTP 域名。
- 后端继续以 `/api/session` 接收 `wx.login` 临时 code，随后签发并验证既有业务 session。不得未经验证地把云托管请求元数据当作家长账户身份。
- 云托管服务按已确认方案保持允许公网访问；正式小程序不配置或使用云托管默认域名和自定义域名作为业务入口。所有外部 HTTP 路由仍须保留既有认证与运营 secret 校验。
- 灰度由云托管控制台按 `openid` 白名单和流量比例完成。发布顺序固定为白名单验证、5%、25%、100%；发生关键异常时立即在控制台回退。小程序不实现灰度版本选择、比例计算或 URL 参数分流。
- 本地 Docker 负责类型检查、自动化测试、数据库迁移、容器启动和基础回滚演练；生产灰度负责 `callContainer`、云托管路由、小程序登录、真实数据库/存储连接与日志验证。
- 私有配置示例应说明开发 API 基址、体验/正式云托管服务名和环境 ID 的配置方法；不得提交真实凭证或生产 API 域名。

## Testing Decisions

- 最高测试 seam 是小程序 API 客户端公开的 `request()` 接口。测试只断言调用方式、路径、请求头、请求体、重试和用户可见错误，不依赖内部传输函数的实现细节。
- 开发版测试验证 HTTPS API 基址调用；体验版和正式版测试验证 `callContainer` 调用、`/api` 路径、`X-WX-SERVICE: ctb`、Bearer token 与 `Idempotency-Key` 透传。
- 验证首次 `/api/session` 登录和 session 失效后的单次重试，在两种传输方式下都保持相同外部行为。
- 验证基础库低于 `2.13.1` 时不发送网络请求，并返回可显示的升级提示。
- 现有 HTTP server seam 测试继续覆盖 `/api` 契约、账户隔离、幂等、运营授权与反馈处理；本需求不得弱化这些测试。
- 本地 Docker 验收验证生产入口可启动、健康检查可用、迁移可执行；云托管验收以测试 `openid` 验证实际 `callContainer` 路由、登录、数据库、存储和日志，再逐级灰度。

## Out of Scope

- 绑定自定义域名、ICP 备案、将默认域名配置为小程序服务器域名。
- 浏览器、H5、公众号网页或第三方系统直接调用业务 API。
- 新建开发或体验云托管环境；首版只使用一个生产云托管环境。
- 用云托管请求元数据替换既有微信登录交换或业务 session。
- 在小程序内实现灰度比例、白名单管理、发布控制台或自动回滚。
- 修改学习循环、错题、复习、讲解、反馈等既有业务 HTTP 契约。

## Further Notes

- 该规格与现有云托管研究中“仅供小程序时建议关闭公网访问”的建议存在冲突。此处保留已确认的“允许公网访问”决定；实现前应由发布负责人重新核对云托管控制台与安全要求，若改为关闭公网访问，不影响 `callContainer` 传输方案，但须更新本规格。
- 服务版本 `v0.1.0` 与讲解版本标识独立于云托管灰度版本。灰度版本是部署路由概念，不得写入学习记录或替代反馈中的讲解/模型/请求版本。
