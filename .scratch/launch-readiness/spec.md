# 数学错题本受控内测上线收口规格

**Status:** ready-for-agent

**Baseline:** 微信数学错题本小程序首发规格。本规格定义首版从本地可演示状态进入受控内测所需的生产化工作；学习闭环产品规则继续以首发规格及 ADR 0001 为准。

## Problem Statement

数学错题本的学习闭环、页面和领域测试已经完成，但当前服务仍以局域网 HTTP、本地 SQLite、模拟微信登录和调试订阅为主。家长无法在真实微信小程序中安全地使用产品；照片与儿童学习数据也缺少可审计的生产存储、保留和删除机制。上线前必须把既有学习体验接入真实平台能力，并确保未成年人数据、AI 处理、故障恢复和发布回滚都具备可验证的边界。

## Solution

先发布受控内测版，而不是立刻公开发布。受控内测版保留已完成的免费学习闭环，关闭真实支付；通过微信云托管、真实微信小程序身份、CloudBase 云存储、腾讯云 MySQL 和受控 AI 服务让少量获邀家长在真机上完成完整流程。服务端继续由学习闭环编排模块决定孩子档案、已确认批改结果、错题、复习和周报的业务状态；微信、对象存储、提醒、模型和运维能力都作为基础设施适配器接入该边界。

## User Stories

1. 作为获邀家长，我想在真实微信小程序中登录，以便不需要手动配置局域网服务。
2. 作为家长，我想在监护人确认前看到隐私摘要并拒绝继续，以便儿童学习数据不会在未经同意时被处理。
3. 作为家长，我想在会话过期后被要求安全重新登录，以便不会因失效令牌看到或修改数据。
4. 作为家长，我想在 HTTPS 环境拍摄或选择题目图片，以便微信客户端能正常上传且传输受到保护。
5. 作为家长，我想在上传失败、网络中断或模型不可用时保留可恢复的草稿并改为手动录入，以便学习机会不因基础设施故障丢失。
6. 作为家长，我想知道照片与识别内容如何被处理、保存和删除，以便能对孩子数据作出知情决定。
7. 作为家长，我想在删除错题、孩子档案或家长账户后让关联照片和学习数据在承诺期限内一并清除，以便真正行使数据控制权。
8. 作为家长，我想只收到自己主动授权的、每天至多一条不含题目内容的复习提醒，以便提醒不会泄露儿童学习信息。
9. 作为家长，我想在未获订阅消息授权或通知发送失败时仍能在首页看到待复习事项，以便提醒故障不影响学习计划。
10. 作为家长，我想在 AI 识别或讲解暂不可用时得到清晰说明，而不是看见貌似确定的错误结果，以便能选择重试、手动录入或稍后继续。
11. 作为内测运营者，我想为每个环境配置独立的小程序身份、域名、存储和模型凭证，以便测试数据与生产数据不混用。
12. 作为内测运营者，我想限制照片与模型请求的大小、频率和成本，以便异常流量不会造成安全或预算风险。
13. 作为内测运营者，我想在不记录令牌、图片内容或微信临时凭证的前提下了解登录、上传、模型和提醒是否成功，以便诊断问题。
14. 作为内测运营者，我想拥有健康检查、备份、恢复和版本回滚流程，以便单点故障不会永久丢失学习数据或延长中断。
15. 作为审核人员，我想看到小程序权限、隐私政策、儿童信息处理、AI 使用说明和数据删除渠道，以便判断产品是否符合适用的平台要求。
16. 作为发布负责人，我想在提交审核前用虚构孩子资料在真机跑完建档、拍题、确认、讲解、保存、复习、周报、提醒开关和删除数据，以便发现本地测试覆盖不到的平台问题。
17. 作为发布负责人，我想先邀请有限数量用户进行内测并观察错误率、识别可用性与成本，以便依据真实数据决定是否扩大范围。
18. 作为家长，我不想在受控内测版中被要求支付或看到可实际购买的订阅，以便产品承诺与已接入能力一致。

## Implementation Decisions

- 首版发布形态固定为受控内测：保留免费权益判断，隐藏或禁用调试订阅升级入口；微信支付和公开商业化发布不在本规格内。
- 微信登录由服务端校验小程序临时登录凭证并将平台身份映射到家长账户。临时凭证、平台密钥和平台身份标识不得返回客户端或写入应用日志；客户端只持有服务端签发、可过期的会话令牌。
- 小程序配置按环境区分。受控内测只能访问登记的 HTTPS API 域名与微信合法域名，仓库不提交真实 AppID、密钥或生产地址。
- 孩子档案保留省份作为未来教材/课程体系差异的预留维度。省份为可选字段；新版本交互只选择和展示省级，不要求城市或区县。服务端和存储继续兼容旧版本已保存的省市数据，但当前学习闭环不根据地区改变识别、讲解或复习逻辑。
- 图片上传改为 CloudBase 云存储直传：服务端为已授权家长的草稿分配短时、单对象、不可跨账户的 `cloudPath`，小程序经 `wx.cloud.uploadFile` 上传并提交不透明 `fileID`。应用服务只处理已验证的对象引用和必要元数据，不接收或持久化 Base64 图片；上传完成后才允许识别和题目确认。
- 对象存储为原图、裁剪图和临时草稿分别定义保留期。默认原图在家长完成确认后删除；仅经家长主动选择的已确认错误题裁剪图可长期保留。删除错题、孩子档案或家长账户必须触发关联对象删除，并用可重试的清理任务处理短暂失败。
- `LearningLoop` 保持学习规则的唯一高层边界。真实微信登录、对象存储、模型提供方、订阅消息和定时调度通过适配器进入 HTTP API；它们不得在客户端或基础设施层自行决定监护人授权、已确认批改结果、复习资格、掌握度或周报。
- AI 适配器必须设置连接和总请求超时、可辨别的失败类别、有限重试及每个家长账户的配额。模型响应仍需经既有结构和置信度校验；任何失败或不可靠识别均保持待确认状态。
- 提醒实现真实微信订阅消息授权、模板发送适配器和受控定时任务。仅在家长开启后评估，每个孩子每天至多发送一条，仅包含昵称、待复习数和安全跳转路径；发送失败不改变复习状态，也不对同一日无限重试。
- 生产服务提供最小化的结构化日志、请求关联 ID、健康检查、错误指标和告警。日志不得包含会话令牌、微信登录凭证、图片内容、完整题干、学生作答或模型请求正文。
- 微信云托管运行 HTTP 服务并使用其健康检查、版本和流量发布能力；容器本地文件系统不得承载学习数据。SQLite 迁移至私有网络连接的腾讯云 MySQL，使用托管备份、恢复演练和版本化发布；迁移前保留加密 SQLite 备份并校验账户范围内数据。
- 腾讯云 MySQL 8.0 是云托管生产环境唯一的学习数据源，使用 TLS、连接池和版本化 `schema_migrations`。连接、schema 或迁移失败时服务必须退出，不得回退 SQLite。关键组合写入使用事务；重复错题、复习完成和每日提醒以唯一约束和幂等结果处理。首发受控内测以空 MySQL 启动，旧 SQLite 导入仅在明确需要时执行。备份恢复目标为 RPO 24 小时、RTO 4 小时，且仅能以虚构数据在隔离环境演练。
- 学习闭环统一迁移为异步接口；SQLite 和内存适配器也通过异步适配器满足同一接口。MySQL 使用 `mysql2/promise` 连接池和参数化查询，事务由存储适配器内部封装，`LearningLoop` 不暴露 SQL 事务细节。存储故障返回 HTTP `503` 和稳定错误码 `storage_unavailable`，不返回部分结果、不回退 SQLite；未提交或幂等查询最多安全重试一次。重复创建错题、复习完成和每日提醒返回首次成功结果，内容竞争更新返回 `409`。服务关闭等待在途数据库操作后再关闭连接池，生产 `/healthz` 检查 MySQL。
- 异步迁移采用方案 A：`LearningLoopStore`、`LearningLoop` 公开方法、HTTP 路由和领域测试一次性统一为 `async`/`await`，不保留同步兼容 API。SQLite 和内存适配器仅作为异步接口的本地实现。实现先以“微信登录、家长账户和孩子档案”作为完整纵向样板，通过类型检查、MySQL 集成测试和重启恢复测试后，再扩展题目、错题、复习与提醒路径。
- 新客户端为创建错题、完成复习和提醒发送提供 `Idempotency-Key`；旧客户端使用资源 ID、复习 ID 和日期键作为兼容幂等键。账户删除在数据库事务中清除全部关系数据，对象存储清理由独立可重试任务完成。schema 迁移采用 expand-contract，破坏性变更至少延后一版；领域绝对时间统一以 UTC 毫秒保存，复习日期和提醒小时按 `Asia/Shanghai` 计算。连接池、查询和事务超时可配置并带安全默认值。
- 上线前冻结隐私政策、监护人确认文案、数据保留期限、模型/图片处理说明、删除数据入口和客服渠道；提交小程序审核所需的权限用途、服务器/域名与生成式 AI 相关材料。

## Testing Decisions

- 测试以 `LearningLoop` 和 HTTP API 为最高 seam。验证真实基础设施适配器时，只断言 API 返回的用户可见状态、持久化边界和外部调用契约，不测试页面实现或第三方 SDK 内部细节。
- 为微信登录适配器测试成功身份交换、无效或过期临时凭证、平台错误、会话续期和敏感凭证不进入响应或日志。
- 为对象存储测试签名权限只限当前家长与单一对象、过期或重复上传被拒绝、对象引用完成后才可识别、删除操作最终清理对象、清理失败可安全重试。
- 为 AI 和 HTTP 边界测试超时、限流、无效模型输出、低置信度、网络中断和手动录入降级，确保这些情况不创建伪确定的已确认批改结果或错题。
- 为提醒适配器测试真实授权状态、模板参数不含题目或作答、日发送上限、撤回授权与发送失败不会改变学习状态。既有提醒领域测试作为先例扩展。
- 为运维能力测试健康检查、配置缺失时的启动失败、日志脱敏、备份恢复演练和可回滚部署检查；不以生产密钥或真实儿童数据执行自动化测试。
- 在微信开发者工具和至少一台真机以虚构孩子资料运行端到端发布清单：登录、建档、拍题、识别修改、讲解、错题保存、复习、周报、提醒开关、单题删除、孩子删除和账户删除。
- 验证孩子档案地区兼容：省份可留空；新建档案只提交省份；旧省市档案可读取且界面只展示省份；旧客户端提交省市不会导致接口错误。
- 现有领域层、HTTP 金路径、适配器和提醒测试是本规格的直接先例；新增测试补齐真实微信、对象存储、调度和生产部署边界。

## Out of Scope

- 微信支付、自动续费、真实订阅购买、退款和公开商业化定价。
- 公开发布、规模化运营、人工客服 SLA、增长投放和营销活动。
- 数学学习闭环的新功能、教师端、学校合作、儿童独立账户、排行榜或社交能力。
- 以生产或真实未成年人数据作为开发、验收或自动化测试样本。
- 承诺 OCR、讲解或变式题绝对正确；模型不可用或不可靠时仍以待确认和手动路径处理。

## Further Notes

- 本规格遵循 ADR 0001：只有家长确认的批改结果可进入错题本、掌握度和薄弱点统计；AI 初判永远不是最终学习记录。
- 受控内测的放量阈值需要在首次部署前由发布负责人确定，至少包含：成功登录率、上传/识别成功率、API 错误率、单用户模型成本、数据删除完成率与无 P0 隐私事件。
- 公开提交小程序审核前应再次核对当时有效的微信平台、未成年人保护和生成式 AI 规则；本规格不构成法律意见。
